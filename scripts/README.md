# Ruby Schema generator

This repository models objects with JSON Schemas in `./schemas`. This guide shows how to:

- Generate starter templates from a schema (YAML or JSON)
- Validate data files against a schema

It uses a small Ruby CLI and the `json_schemer` gem, matching the repo's Ruby tooling.

## Install

```bash
bundle install
```

## CLI usage
```bash
# List available schemas
bundle exec ruby scripts/schema_cli.rb list-schemas

# Generate a YAML template for a schema (required fields by default)
bundle exec ruby scripts/schema_cli.rb template project > templates/project.yml

# Generate including optional fields
bundle exec ruby scripts/schema_cli.rb template project --include-optional > templates/project-all.yml

# JSON output
bundle exec ruby scripts/schema_cli.rb template project --format json > templates/project.json

# Validate one or more files against a schema
bundle exec ruby scripts/schema_cli.rb validate project templates/project.yml
bundle exec ruby scripts/schema_cli.rb validate schemas/project-schema.json templates/project.json

# Generate templates for ALL schemas (JSON + YML)
bundle exec ruby scripts/schema_cli.rb generate-templates

# Only one format
bundle exec ruby scripts/schema_cli.rb generate-templates --only json
bundle exec ruby scripts/schema_cli.rb generate-templates --only yml

# Output to a different directory
bundle exec ruby scripts/schema_cli.rb generate-templates --out-dir tmp/templates
```

Notes:
- Schema may be specified by its name (e.g., `project`) or by a path (e.g., `schemas/project.json`).
- The templates generated by `generate-templates` always include ALL fields (required and optional) to provide complete, ready-to-fill files.
- The validator prints per-file status (OK/FAIL/ERROR) and a summary. It resolves inter-schema references offline.

## Recommended repo structure

```
schemas/
  <object>-schema.json

templates/
  <object>/
    <your-files>.yml
```

## Content formats for rich text fields

For fields that may contain Markdown or HTML (e.g., `definition`), we store:
- The content as a string field
- A companion `...Format` field with a media type: `text/markdown`, `text/html`, or `text/plain`

This is explicit, easy to validate, and plays well with renderers.

## CSV input (optional)

CSV often represents lists rather than single objects. If you need CSV:
- Create a mapping file (YAML) that maps CSV headers to schema JSON Pointers (e.g., `/title`, `/authors/0/name`).
- Convert CSV -> JSON using the mapping, then validate JSON with the CLI.

We can add a converter in `scripts/` if/when you want to standardize CSV ingestion.
